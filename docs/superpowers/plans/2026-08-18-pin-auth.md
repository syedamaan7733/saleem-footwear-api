# PIN-based Authentication Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace password login with a 6-digit numeric PIN across the API, website, and mobile app, with per-account brute-force lockout, self-service Change PIN, and admin-assisted reset.

**Architecture:** The stored credential stays bcrypt-hashed in the existing User `password` field (no DB rename) but now holds a 6-digit PIN. The API accepts either `pin` or `password` on login/register for mobile version-skew backward compatibility. Brute-force protection is per-account state (`failedPinAttempts`, `lockUntil`) persisted on the User document because the API runs on Vercel serverless where in-memory rate-limit stores are unreliable. Website and mobile are relabeled "Password" → "PIN" with numeric input and gain Change-PIN UI; the admin customer list gains a Reset-PIN action.

**Tech Stack:** Express + Mongoose + bcryptjs (API); React + Vite + Chakra UI (website); Expo / React Native + react-hook-form + zod (mobile). API tests: Jest + supertest + mongodb-memory-server (added by this plan).

**Spec:** `saleem-footwear-api/docs/superpowers/specs/2026-08-18-pin-auth-design.md`

## Global Constraints

- PIN format is exactly 6 digits: regex `^\d{6}$`. Enforced at the controller layer (stored value is a bcrypt hash and cannot be schema-validated post-hash).
- Shared temporary PIN for existing users and admin reset: `966900`.
- Lockout threshold: **10** failed attempts → **5-minute** cooldown (`5 * 60 * 1000` ms).
- API login/register must accept BOTH `pin` and `password` request fields, preferring `pin`.
- DB field name stays `password`; user-facing copy says "PIN".
- Do NOT touch the unrelated uncommitted `app.js` image-upload change already in the API working tree beyond the explicit refactor in Task 1.
- Commit messages: simple, no co-author trailer.
- Work branch in every repo: `feat/pin-auth` (already created).
- API semantic-release only fires on the `saleemapi` branch — never merge/commit there as part of this work.

- [ ] **Step 3: Rewrite `logIn`**

In `controllers/authControllers.js`, replace the body of `logIn` with:

```js
const LOCK_MAX_ATTEMPTS = 10;
const LOCK_WINDOW_MS = 5 * 60 * 1000;

const logIn = async (req, res) => {
  const { identifier } = req.body;
  const credential = req.body.pin ?? req.body.password;
  if (!identifier || !credential) {
    throw new CustomError.BadRequestError(
      "Please provide phone/email and PIN"
    );
  }

  const isEmail = validator.isEmail(identifier);
  const user = isEmail
    ? await User.findOne({ email: identifier })
    : await User.findOne({ phone: identifier });

  if (!user) {
    throw new CustomError.UnauthenticatedError("Invalid Credential");
  }

  // Locked out?
  if (user.lockUntil && user.lockUntil.getTime() > Date.now()) {
    const mins = Math.ceil((user.lockUntil.getTime() - Date.now()) / 60000);
    throw new CustomError.UnauthenticatedError(
      `Too many attempts. Try again in ${mins} minute(s).`
    );
  }

  const isCorrect = await user.comparePassword(credential);
  if (!isCorrect) {
    user.failedPinAttempts = (user.failedPinAttempts || 0) + 1;
    if (user.failedPinAttempts >= LOCK_MAX_ATTEMPTS) {
      user.lockUntil = new Date(Date.now() + LOCK_WINDOW_MS);
      user.failedPinAttempts = 0;
    }
    await user.save();
    throw new CustomError.UnauthenticatedError("Invalid PIN");
  }

  // success — clear any lock state
  if (user.failedPinAttempts !== 0 || user.lockUntil !== null) {
    user.failedPinAttempts = 0;
    user.lockUntil = null;
    await user.save();
  }

  const userToken = createTokenUser(user);
  const token = createJWT({ payload: userToken });
  res.status(StatusCodes.OK).json({ token, userToken });
};
```

(`comparePassword` and the JWT helpers are unchanged. Note `user.save()` will re-run the `pre("save")` hook, which returns early because `password` was not modified — so the PIN is not re-hashed.)

```js
const changePin = async (req, res) => {
  const { currentPin, newPin } = req.body;
  if (!currentPin || !newPin) {
    throw new CustomError.BadRequestError(
      "Please provide current and new PIN."
    );
  }
  if (!validatePin(newPin)) {
    throw new CustomError.BadRequestError("New PIN must be exactly 6 digits.");
  }
  if (currentPin === newPin) {
    throw new CustomError.BadRequestError(
      "New PIN must be different from current PIN."
    );
  }

  const user = await User.findOne({ _id: req.user.userId });
  if (!user) {
    throw new CustomError.UnauthenticatedError("Invalid Authentication...");
  }

  const isCorrect = await user.comparePassword(currentPin);
  if (!isCorrect) {
    throw new CustomError.UnauthenticatedError("Current PIN is incorrect.");
  }

  user.password = newPin; // pre-save hook re-hashes
  user.failedPinAttempts = 0;
  user.lockUntil = null;
  await user.save();

  res.status(StatusCodes.OK).json({ msg: "PIN updated successfully." });
};
```

### Task 7: One-off migration — seed existing users to 966900

**Files:**

**Interfaces:**
- Consumes: `db/connect`, `models/User`. Standalone script run manually with `MONGO_URI` set.

- [ ] **Step 1: Write the migration script**

Create `scripts/seed-pins.cjs`:

```js
require("dotenv").config();
const mongoose = require("mongoose");
const connectDB = require("../db/connect");
const User = require("../models/User");

const TEMP_PIN = "966900";

async function run() {
  await connectDB(process.env.MONGO_URI);
  const users = await User.find({});
  let updated = 0;
  for (const user of users) {
    user.password = TEMP_PIN; // pre-save hook hashes it
    user.failedPinAttempts = 0;
    user.lockUntil = null;
    await user.save();
    updated += 1;
  }
  console.log(`Seeded temp PIN for ${updated} user(s).`);
  await mongoose.connection.close();
}

run().catch(async (err) => {
  console.error(err);
  await mongoose.connection.close();
  process.exit(1);
});
```
